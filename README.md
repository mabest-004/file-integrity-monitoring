# File Integrity Monitoring (FIM)

A simple Python-based File Integrity Monitoring (FIM) tool for detecting unauthorized or unexpected file changes.

The program creates a baseline of files using cryptographic hash functions and compares the current state of files against the stored baseline.

It can detect content changes, new files, deleted files, file size changes, and modification time changes.

---

## Features

* Create a file integrity baseline
* Calculate cryptographic hashes
* Support multiple hash algorithms
* Detect modified files
* Detect new files
* Detect deleted files
* Detect file size changes
* Detect modification time changes
* Store baseline information in `hash.json`
* Log detected changes in `change.log`
* Perform one-time integrity checks
* Continuously monitor files using `--watch`
* Configure monitoring intervals using `--time`
* Prevent changing the hashing algorithm during `--update` and `--check`
* Handle `Ctrl+C` gracefully during real-time monitoring

---

## Supported Hash Algorithms

The project supports the following algorithms:

### SHA-2

* SHA-224
* SHA-256
* SHA-384
* SHA-512

### SHA-3

* SHA3-224
* SHA3-256
* SHA3-384
* SHA3-512

### BLAKE2

* BLAKE2b
* BLAKE2s

### Legacy Algorithms

* SHA-1
* MD5

> **Security Note:** MD5 and SHA-1 are included for educational purposes and compatibility. They are not recommended for modern security-sensitive applications. SHA-256, SHA-512, SHA-3, or BLAKE2 are recommended.

# How It Works

The program works using a baseline comparison system.

```text
                ┌─────────────┐
                │   --init    │
                └──────┬──────┘
                       │
                       ▼
                 Create baseline
                       │
                       ▼
                  hash.json
                       │
             ┌─────────┴─────────┐
             │                   │
             ▼                   ▼
         --check              --watch
             │                   │
             │              Continuous check
             │                   │
             └─────────┬─────────┘
                       ▼
                 Detect changes
                       │
                       ▼
                   --update
                       │
                       ▼
                New baseline
```

For every monitored file, the program stores:

* Hash value
* File size
* Modification time

Example:

```json
{
    "algorithm": "sha256",
    "example.txt": {
        "hash": "....",
        "filesize": 1024,
        "modification_time": 1754100000.0
    }
}
```

During a check, the current values are compared with the stored baseline.

# Usage

General syntax:

```bash
python fim.py [OPTIONS] [ALGORITHM]
```

Available options:

```text
-i, --init       Initialize the program
-u, --update     Update the baseline
-c, --check      Check for changes
-w, --watch      Real-time monitoring
-t, --time       Monitoring interval in seconds
```

---

# 1. Initialize

Initialize the program using the default SHA-256 algorithm:

```bash
python fim.py --init
```

You can specify an algorithm:

```bash
python fim.py --init sha256
```

For example:

```bash
python fim.py --init sha512
```

or:

```bash
python fim.py --init sha3_256
```

After initialization, the program creates:

```text
hash.json
```

The file contains the baseline information of the monitored files.

If `hash.json` already exists, the program will not overwrite it.

Example:

```text
hash.json already exists. Please use --update.
```

---

# 2. Check for Changes

Perform a one-time integrity check:

```bash
python fim.py --check
```

The program compares the current state of the files with the baseline stored in `hash.json`.

### Content Changed

```text
Content changed: path/to/file.txt
```

The calculated hash is different from the stored hash.

### File Size Changed

```text
Size changed: path/to/file.txt
```

The file size is different from the stored value.

### Modification Time Changed

```text
Modification time changed: path/to/file.txt
```

The modification timestamp is different from the stored value.

### New File

```text
The file path/to/new_file.txt is new
```

A file exists in the current directory but not in the baseline.

### Deleted File

```text
The file path/to/old_file.txt was deleted
```

A file exists in the baseline but no longer exists in the current directory.

Detected changes are also written to:

```text
change.log
```

---

# 3. Update the Baseline

When file changes are intentional, the baseline can be updated:

```bash
python fim.py --update
```

The program reads the algorithm stored in `hash.json` and uses the same algorithm to generate a new baseline.

For example:

```text
Initial algorithm:
SHA-256

        ↓

File changes

        ↓

--update

        ↓

New baseline using SHA-256
```

The program prevents the user from accidentally changing the hashing algorithm during an update.

For example:

```bash
python fim.py --update md5
```

If the stored algorithm is SHA-256, the program reports an algorithm mismatch.

---

# 4. Real-Time Monitoring

The `--watch` option continuously checks the monitored files.

```bash
python fim.py --watch
```

The default monitoring interval is:

```text
60 seconds
```

The program can be stopped using:

```text
Ctrl+C
```

The program handles `KeyboardInterrupt` and exits cleanly without displaying a Python traceback.

---

# 5. Custom Monitoring Interval

The `--time` option can be used with `--watch` to specify the interval between checks.

For example, check every 10 seconds:

```bash
python fim.py --watch --time 10
```

Check every 30 seconds:

```bash
python fim.py --watch --time 30
```

The value must be greater than zero.

```bash
python fim.py --watch --time 0
```

is invalid.

The `--time` option cannot be used without `--watch`.

For example:

```bash
python fim.py --time 10
```

is invalid.

---

# Hash Algorithm Selection

The hashing algorithm is selected when the baseline is initialized.

Example:

```bash
python fim.py --init sha256
```

The selected algorithm is stored in `hash.json`.

During `--check` and `--update`, the program verifies that the selected algorithm matches the stored algorithm.

This prevents accidentally comparing files using different hashing algorithms.

---

# Files Excluded from Monitoring

The following files are automatically excluded:

```text
hash.json
change.log
```

This prevents the program from monitoring its own baseline and log files.

---

# Logging

Detected changes are written to:

```text
change.log
```

The logging format contains:

* Timestamp
* Log level
* Event description

Example:

```text
2026-09-06 12:30:00,123 - WARNING - Content changed: test.txt
```

# Security Considerations

File integrity monitoring depends heavily on the security of the baseline.

If an attacker can modify both:

```text
hash.json
```

and the monitored files, the integrity check can potentially be bypassed.

For a more secure implementation, future versions could store the baseline in a protected location or use an external trusted system.

The project also includes MD5 and SHA-1 for educational purposes, but stronger algorithms such as SHA-256, SHA-512, SHA-3, and BLAKE2 should be preferred.

---

# Limitations

This is an educational File Integrity Monitoring project.

Current limitations include:

* Monitoring is based on periodic scanning.
* It does not currently use operating-system file-system events.
* The baseline is stored locally in `hash.json`.
* An attacker with write access to the baseline could potentially modify it.
* The program monitors the current working directory recursively.
* File paths are stored directly in `hash.json`.
* Files that change while being hashed may produce inconsistent results.
